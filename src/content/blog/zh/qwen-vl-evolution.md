2023 年的 Qwen-VL 会看图、读字、回答问题，也能把物体框出来。三年以后，Qwen3.5 已经把图像和视频纳入主模型的默认输入，还要同时处理长上下文、工具调用和界面操作。中间几代模型的名字很接近，内部变化却远比版本号显得更大。

我把五代官方论文、博客、仓库和模型卡对在一起以后，最清楚的一条线索是视觉信息怎样逐渐摆脱固定接口。初代先把一张图片压成固定数量的 token。Qwen2-VL 开始尊重原始宽高比。Qwen2.5-VL 把真实时间带进视频位置编码。Qwen3-VL 让不同深度的视觉特征更早进入语言主干。到了 Qwen3.5，多模态进入统一模型，VL 后缀也随之退出官方命名。

这篇文章按技术变化来讲，也保留几个容易混淆的数字。benchmark 数值均为官方报告结果。不同代际使用的提示模板、输入分辨率、评审模型和数据版本常有差异，数字适合观察各代重点，不能当作严格同条件排行榜。

## 先把 Qwen3.5 的名字说清楚

官方没有发布一个独立命名为 `Qwen3.5-VL` 的模型家族。官方模型名只有 Qwen3.5，模型 ID 包括 `Qwen3.5-397B-A17B`、`Qwen3.5-27B` 和 `Qwen3.5-4B` 等。它从预训练阶段统一处理文本、图像与视频，官方称其为原生视觉语言模型。

社区讨论里偶尔会写 Qwen3.5-VL，用来强调视觉能力。检索权重、代码和部署文档时，应当使用 Qwen3.5 这个正式名字。截至 2026-08-12，Qwen3.6 也已发布。本文依照既定范围停在 Qwen3.5，不把后续版本混进这条时间线。

## 五代模型放在一张时间线上

| 代际 | 首次公开 | 官方规模 | 这一代解决的主要问题 |
| --- | --- | --- | --- |
| Qwen-VL | 2023-08 | 约 9.6B 总参数 | 建立中文与英文图像理解、OCR、问答和视觉定位的基础接口 |
| Qwen2-VL | 2024-08 | 2B、7B、72B | 动态分辨率、图像视频统一表示、长视频和视觉 Agent |
| Qwen2.5-VL | 2025-01 | 3B、7B、72B，后增 32B | 动态帧率、真实时间定位、文档解析和 GUI 操作 |
| Qwen3-VL | 2025-09 | 2B、4B、8B、32B、30B-A3B、235B-A22B | DeepStack、Thinking 模式、256K 长上下文和更强空间推理 |
| Qwen3.5 | 2026-02 | 0.8B 至 397B-A17B | 统一多模态主模型、混合线性注意力和原生 Agent 能力 |

这条时间线旁边还有两个支线。Qwen-VL-Plus 与 Qwen-VL-Max 是 2023 年末到 2024 年初推出的闭源 API 产品，没有对应的公开权重。QvQ-72B-Preview 是 2024 年 12 月发布的视觉推理实验模型，后来 Qwen3-VL 把 Thinking 模式纳入了主系列。它们都很重要，但不宜当成新的开源主代际。

## Qwen-VL 先把视觉接到 Qwen 上

[Qwen-VL 论文](https://arxiv.org/abs/2308.12966) 给出的结构很直白。视觉编码器使用 OpenCLIP 的 ViT-bigG，约 1.9B 参数。语言部分来自 Qwen-7B，论文参数表记为约 7.7B。两者之间放入一个约 0.08B 的单层 cross-attention adapter，整套模型约 9.6B。

adapter 使用一组可学习 query，把视觉编码器输出压缩成固定 256 个视觉 token，再交给语言模型。这个设计给模型提供了稳定接口，也提前设定了信息瓶颈。内容简单的照片和密集文档都要通过同样数量的 token。

### 固定分辨率与坐标

第一阶段视觉预训练使用 224 像素输入，后续多任务阶段将分辨率提高到 `448 × 448`。图片需要进入固定画布，极长截图、小字文档和特殊宽高比都会经过缩放。

Qwen-VL 已经支持视觉 grounding。模型能够在文本中输出边界框，坐标被归一化到 `[0, 1000)`。这套表示让问答、文字描述与物体定位进入同一条生成序列。多图输入、中文 OCR 和细粒度定位也因此可以组合起来。

### 三阶段训练

论文记录了很清楚的训练顺序。

1. 视觉与语言对齐阶段从约 5B 原始图文对中清洗出约 1.4B 样本。Qwen 语言模型保持冻结，只训练视觉编码器和 adapter，输入分辨率为 224。
2. 多任务预训练阶段把分辨率提高到 448，并解冻全部参数。数据覆盖 caption、VQA、grounding、OCR 和纯文本任务。
3. 指令微调阶段使用约 350K 对话样本，冻结视觉编码器，更新语言模型与 adapter，得到 Qwen-VL-Chat。

第二阶段的数据组成也能看出当时的重点。论文列出 19.7M caption、3.6M VQA、24.8M OCR，以及两类各 8.7M 的 referring grounding 与 grounded caption 数据。纯文本数据有 7.8M，用来减少视觉训练对语言能力的干扰。

### 它建立了什么基线

官方论文报告 Qwen-VL 在 VQAv2 得到 79.5，在 TextVQA 得到 63.8，在 DocVQA 得到 65.1，在 ChartQA 得到 65.7。RefCOCO val 的结果为 89.36。今天看这些数字已经不高，当时它们说明一套中文开放权重模型可以同时完成通用问答、读字和定位。

初代的限制也很清楚。固定分辨率会损失小字与极端宽高比信息，固定 256 个视觉 token 无法随内容密度调整预算，模型也没有原生长视频接口。它更像一个能看图的对话模型，尚未形成后面几代那种持续观察和行动循环。

Qwen-VL 与 Qwen-VL-Chat 发布了权重，后来又增加 Int4、LoRA 和 Q-LoRA 支持。它使用早期自定义 Qwen License，商业使用带有协议条件。后续几代才普遍切换到 Apache 2.0。

## Qwen2-VL 让图片保留自己的形状

Qwen2-VL 于 2024-08 公布。首批开放 2B 与 7B，72B 最初通过 API 提供，随后也发布了权重。公开模型名使用 2B、7B 和 72B。论文参数表将共享视觉编码器记为约 675M，三个语言主干约为 1.5B、7.6B 和 72B，所以中型模型在论文表格里也会按约 8B 讨论。

这一代最重要的变化叫 Naive Dynamic Resolution。名字朴素，影响很大。图像不再统一挤进固定正方形，视觉 token 数量会随着原始分辨率和宽高比改变。网页长截图可以保留纵向结构，文档小字也能得到更多 token。部署者同时要承担一个新变量，输入像素越多，显存占用和推理时间越高。

### 二维位置与视觉 token

Qwen2-VL 的视觉编码器去掉固定绝对位置编码，使用 2D-RoPE 表达横纵位置。相邻 `2 × 2` patch 经 MLP 合并，减少进入语言模型的视觉 token 数。动态分辨率因此没有直接把计算量扩大四倍。

语言侧引入 M-RoPE。旋转位置编码的一部分维度负责时间，一部分负责高度，另一部分负责宽度。同一套语言主干于是能区分词序、图像二维位置和视频时间位置。

### 图像与视频使用统一接口

视频编码使用时间深度为 2 的 3D convolution，相邻帧先在时间维组合。静态图像会复制成两帧，从而走过同一套视觉接口。官方训练与推理设置通常按 2 fps 采样视频，并限制视觉 token 总量，论文给出的上限为 16,384。

这种统一方式让 Qwen2-VL 能处理 20 分钟以上的视频。这里的长视频已经经过采样和 token 压缩，模型没有逐帧保留原始码流。很短的动作、转瞬即逝的文字和高频状态变化仍可能落在采样间隔里。

### 训练数据向视频和行动扩展

Qwen2-VL 继续采用三阶段方案，顺序为视觉编码器训练、全参数多模态训练和指令对齐。论文报告主要预训练阶段约使用 600B 与 800B token，合计约 1.4T 多模态 token，训练数据截止到 2023-06。

数据类型开始明显扩张。除了图文、OCR、VQA 与交错网页，还加入视频问答、视觉 grounding、多轮对话、手机操作和机器人任务。模型输出也不再局限于一句回答。它可以读取界面，给出下一步操作位置，随后根据新截图继续判断。

官方 72B 结果里，DocVQA 为 96.5，TextVQA 为 85.5，OCRBench 为 877，MMMU 为 64.5。Video-MME 在无字幕与有字幕设置下分别为 71.2 和 77.8。AITZ 的动作精确匹配为 72.1。这些结果对应了这一代的三个投入方向，文档、视频和视觉行动。

Qwen2-VL 的 2B 与 7B 采用 Apache 2.0，72B 开放后也使用同一许可证。2B 让端侧和低显存试验有了入口，7B 成为常用部署档，72B 面向质量优先的服务器场景。

## Qwen2.5-VL 开始认真处理时间和界面

Qwen2.5-VL 于 2025-01 发布 3B、7B 和 72B 的 Base 与 Instruct 权重。2025-03 又加入 32B-Instruct，官方说明这个版本经过人类偏好对齐。四个规模均使用 Apache 2.0。

这一代重新训练了视觉编码器。论文配置为 1280 hidden size、32 层和 14 像素 patch。绝大多数层使用大小为 112 的窗口注意力，第 7、15、23 和 31 层使用全局注意力。窗口层省下计算，全局层负责跨区域交换信息。相邻四个视觉 patch 仍会在送入语言模型前合并。

### 动态帧率与真实秒数

Qwen2-VL 已经能看视频，时间位置仍更接近采样后的帧序号。Qwen2.5-VL 增加 dynamic FPS，并让 M-RoPE 的时间位置与真实时间对齐。不同帧率的视频可以共享秒这一尺度，模型也更容易回答事件在第几秒出现。

官方把视频能力推进到一小时以上，并重点训练秒级事件定位。实际推理仍需要在帧数、分辨率和上下文预算之间取舍。一小时视频经过稀疏采样后适合找主要事件，毫秒级动作和快速字幕需要更高采样率或先切片。

### 4.1T token 从哪里来

[Qwen2.5-VL 论文](https://arxiv.org/abs/2502.13923) 报告总训练量约 4.1T token。

1. 第一阶段约 1.5T，训练视觉编码器，序列长度为 8192。
2. 第二阶段约 2T，进行全参数多模态训练，序列长度仍为 8192。
3. 第三阶段约 0.6T，扩展到 32768 长度，继续训练全部参数。

数据覆盖图像描述、知识、OCR、图文交错文本、VQA、视频、grounding、文档、Agent 和纯文本。后训练还使用数据过滤与 rejection sampling 来提高指令质量。

这里有一处官方口径差异。Qwen2-VL 自己的论文报告约 1.4T token，Qwen2.5-VL 论文回顾前代时写成 1.2T。两份论文可能采用了不同统计范围。本文保留各自原文数字，不自行合并出第三个数字。

### 从坐标输出走向可执行结构

Qwen2.5-VL 可以输出边界框或点，也能把扫描文档、表格和页面布局整理成稳定 JSON。GUI 场景因此少了一层脆弱的文本解析。模型读出按钮位置，调用外部控制器点击，再根据下一张截图继续执行。

官方 72B 报告中，MMMU 为 70.2，MathVista 为 74.8，CC-OCR 为 79.8，CountBench 为 93.6。ScreenSpot Pro 为 43.6，AndroidWorld 为 35.0。这里已经能看到感知与行动同时进入评测。

GUI 分数不能直接兑换成无人值守的产品可靠性。截图缩放、系统主题、弹窗和延迟都会改变坐标。投入部署时仍要限制可执行动作，保存每一步截图，并为付款、删除和发送等操作设置确认门槛。

## Qwen3-VL 让视觉特征更早进入推理

Qwen3-VL 从 2025-09 开始分批发布。首批是 235B-A22B 的 Instruct 与 Thinking，随后增加 30B-A3B、2B、4B、8B 和 32B。四个 dense 规模与两个 MoE 规模覆盖了端侧实验、单机部署和高端服务器。主要型号都有直接回答与显式思考版本。

模型原生支持 256K 上下文，官方仓库给出扩展到 1M 的方式。上下文上限扩大以后，图像像素和视频帧仍要经过视觉 token 预算。把上限写进配置不会让显存、预填充时间和注意力代价消失。

### SigLIP2、DeepStack 与交错位置编码

视觉编码器转向 SigLIP2 体系，继续采用动态分辨率、2D-RoPE 和 `2 × 2` 合并。Qwen3-VL 又加入 DeepStack，从视觉编码器的三个深度抽取特征，分别注入语言模型前面的三层。细粒度纹理、局部边缘与较高层语义因此不用先全部挤过最后一个视觉表示。

位置编码也得到调整。旧版 M-RoPE 把时间、高度和宽度分配到连续的频率区间，三个轴得到的频谱并不均衡。Interleaved MRoPE 将三个轴交错分布到不同频率，使空间与时间信息都能使用高低频成分。

视频时间改成显式文本时间戳。类似 `<3.0 seconds>` 的 token 会随帧进入序列。模型可以直接引用时间，长视频事件定位也更容易与自然语言回答接上。

### 四段预训练与 Thinking 后训练

论文把预训练分成四段。

| 阶段 | 训练参数 | 数据量 | 序列长度 |
| --- | --- | --- | --- |
| S0 | 只训练视觉语言 merger | 约 67B token | 8192 |
| S1 | 全参数 | 约 1T token | 8192 |
| S2 | 全参数 | 约 1T token | 32768 |
| S3 | 全参数 | 约 100B token | 262144 |

数据加入长图文交错书籍、重新生成的高质量描述、OCR 与文档、grounding、计数、三维和空间关系、代码、STEM、视频与 Agent 轨迹。后训练使用长链条 SFT、教师蒸馏和强化学习。论文记录约 1.2M 条 SFT 数据，其中约三分之一是纯文本，其余为图像或视频任务，并按 32K 与 256K 两个长度阶段训练。

Thinking 模式对数学、空间关系和多步视觉任务更有用，也会增加生成时间。简单 OCR、图片分类或界面元素查找往往用 Instruct 就够了。部署时让路由器按任务难度选择模式，比让所有请求都产生长思考更省资源。

### 视频、空间与视觉 Agent

Qwen3-VL 把空间推理、三维关系、长文档和视觉代码生成列为重点。官方 235B-A22B 结果里，MMLongBench-Doc 的 Instruct 与 Thinking 分别为 57.0 和 56.2，MuirBench Thinking 为 80.1。EmbSpatial、RefSpatial 和 RoboSpatial-Home 分别报告 84.3、69.9 和 73.9。

这些能力让模型更适合网页、桌面和移动设备 Agent。模型仍只负责从视觉状态提出动作，外部 harness 决定怎样执行、验证和回滚。多步任务里的一个坐标偏差会改变后续全部截图，单步 benchmark 无法覆盖这种误差累积。

## Qwen3.5 把多模态放进主模型

Qwen3.5 的首个开放模型是 2026-02 发布的 397B-A17B。随后发布 122B-A10B、35B-A3B、27B，以及 9B、4B、2B 和 0.8B。全系列采用 Apache 2.0。

官方博客将它描述为原生视觉语言模型。训练从早期阶段混合文本、图像和视频，语言与视觉不再各自使用一套产品命名。官方只公开数据量达到数万亿多模态 token，没有给出可核对的精确总数。这里不宜根据前代规模猜一个数。

### 混合线性注意力主干

Qwen3.5 的文本主干采用 Gated DeltaNet 与 Gated Attention 混合结构。每三层线性注意力之后放一层完整注意力，以三比一的比例重复。线性层降低长序列成本，完整注意力定期补充全局交互。稀疏型号在这些层中结合 MoE，并使用 multi-token prediction。

旗舰 397B-A17B 共 60 层，hidden size 为 4096，总参数约 397B，每个 token 激活约 17B。模型有 512 个 experts，每次路由 10 个，另有一个 shared expert。60 层可看成 15 组四层单元，每组包含三层 Gated DeltaNet 与一层 Gated Attention。

27B dense 版本有 64 层，hidden size 为 5120，由 16 组同样的四层单元组成。Qwen3.5 使用 248,320 词的词表，官方概括为约 250K，并把语言与方言覆盖扩展到 201 种。

视觉接口延续 Qwen3-VL 的动态视觉编码路线。模型卡直接提供图文输入范例，视频也属于官方原生多模态能力。语言主干更适合长序列以后，视频和多页文档仍会受到视觉采样、像素预算与显存的共同约束。

### 上下文与官方结果

开放权重的原生上下文为 262,144。官方配置支持扩展到 1,010,000 token，托管版 Qwen3.5-Plus 默认提供 1M。长上下文部署需要单独评估 KV cache、预填充时延和并发，最大长度很少等于日常最经济的长度。

397B-A17B 的官方报告结果包括 MMMU 85.0、MMMU-Pro 79.0、MathVision 88.6、MathVista 90.3、OmniDocBench 1.5 90.8 和 CC-OCR 82.0。

27B 在 MMMU 得到 82.3，在 MathVision 得到 86.0。Video-MME 的无字幕与有字幕结果为 82.8 和 87.0，ScreenSpot Pro 为 70.3，OSWorld-Verified 为 56.2，AndroidWorld 为 64.2。较小的 dense 模型已经能覆盖复杂视觉问答、视频和界面行动，也更适合单机部署。

## 五代变化怎样连起来

| 技术维度 | Qwen-VL | Qwen2-VL | Qwen2.5-VL | Qwen3-VL | Qwen3.5 |
| --- | --- | --- | --- | --- | --- |
| 图像分辨率 | 固定 448 | 原生动态分辨率 | 动态分辨率与高效窗口 ViT | SigLIP2 与 DeepStack | 延续动态视觉接口并统一进主模型 |
| 视觉 token | 固定 256 | 随图像尺寸变化 | 随像素预算与任务变化 | 多层视觉特征进入语言主干 | 与长序列混合注意力共同工作 |
| 位置表示 | 固定二维位置 | 2D-RoPE 与 M-RoPE | 时间轴对齐真实秒数 | Interleaved MRoPE 与文本时间戳 | 延续原生图像视频位置处理 |
| 视频 | 无原生长视频设计 | 2 fps 采样与统一图像视频接口 | 动态帧率和一小时以上视频 | 长视频、事件定位与 Thinking | 统一多模态 Agent 输入 |
| 行动能力 | 框选和视觉问答 | 手机与机器人任务 | 点、框、JSON 与 GUI | 网页、桌面、移动设备 Agent | 原生多模态工具使用与行动 |
| 上下文 | 早期对话长度 | 受视觉 token 上限约束 | 32K 长训练 | 原生 256K，可扩展 1M | 原生 262K，可扩展约 1M |

这张表里最持久的变化是视觉预算开始跟着内容走。模型随后获得真实时间、结构化输出和多层视觉注入。Agent 能力才有了更稳的基础。仅靠一个更大的语言主干，无法补回缩放时已经丢掉的小字，也无法知道视频采样间隙里发生了什么。

## 部署时怎样选

### 历史复现与教学

Qwen-VL 适合复现第一代视觉语言接口，或者研究固定视觉 token 的行为。它的许可证、依赖和能力都已经落后于后续版本，新项目通常没有必要从它起步。

Qwen2-VL 适合研究动态分辨率与 M-RoPE，也能作为资源紧张场景的稳定基线。2B 便于边缘设备试验，7B 能覆盖常见 OCR、VQA 和短视频任务。它对文档结构、长视频时间和 GUI 的处理弱于 Qwen2.5-VL。

### 文档、视频和 GUI

Qwen2.5-VL 仍是很实用的专用 VL 选择。3B 与 7B 适合本地 OCR、票据和页面理解，32B 在成本与视觉推理之间比较均衡，72B 用于质量优先的服务器。需要秒级视频定位、稳定 JSON、点选或 GUI 操作时，它比 Qwen2-VL 更合适。

Qwen3-VL 适合需要长文档、空间推理、显式 Thinking 和多步视觉 Agent 的系统。8B 与 32B dense 模型部署直接，30B-A3B 用较低激活参数换取更大总容量，235B-A22B 面向多卡服务器。MoE 的激活参数少，完整权重、通信和显存管理仍有明显成本。

### 统一文本与多模态 Agent

新系统若希望一个模型同时处理纯文本、图像、视频和工具任务，Qwen3.5 的统一接口更省工程分支。0.8B、2B 和 4B 适合能力验证与受限设备，9B 与 27B 更适合本地高质量推理。35B-A3B 和 122B-A10B 提供稀疏路线，397B-A17B 需要成熟的分布式推理设施。

选模型时先量输入，再看参数。文档任务要统计每页像素和页数，视频任务要明确 fps、最大帧数和时长，GUI 任务还要计算连续截图带来的上下文增长。模型卡里的最大 context 只是硬上限，日常吞吐由常用输入分布决定。

### 量化、许可证与实现版本

Qwen-VL 使用自定义许可证。Qwen2-VL 之后的主系列大多采用 Apache 2.0，部署前仍应逐个核对模型卡。官方为若干代际提供 AWQ、GPTQ 或低比特版本。量化会影响 OCR 小字、坐标和细粒度视觉判断，不能只用纯文本 perplexity 判断损失。

动态分辨率模型通常允许设置最小与最大像素。降低上限能明显节省视觉 token，密集文档也会先受损。一个稳妥流程是用真实页面和视频建立小型回归集，再同时选择像素预算、帧率、量化方式与模型规模。

## 仍然没有解决的问题

### benchmark 不能代替自己的数据

官方表格能说明研发重点，无法覆盖具体输入。扫描件的噪声、手写字、企业内部界面和专业视频都可能离公开数据很远。跨代比较还会碰到测试集更新、prompt 变化与评审器变化。

### 长视频仍依赖取舍

一小时视频能力来自采样、压缩和长上下文协作。稀疏采样适合事件概览，容易漏掉极短动作。高 fps 能保留细节，很快又会耗尽视觉 token。可靠系统通常先做镜头或事件切分，再对可疑片段提高采样率。

### 长上下文没有自动变成长记忆

模型可以接收更多页和更多帧，仍可能忘记早期约束、混淆重复人物，或者把摘要中的错误带到后面。持续视频与长任务需要外部状态、证据索引和回看机制。上下文长度解决容量，记忆更新与验证仍由系统设计承担。

### GUI 行动需要安全边界

界面布局会变化，坐标会受缩放影响，弹窗也可能遮挡目标。模型一次误点以后，后续状态全部改变。执行器需要检查当前截图与预期是否一致，对高风险动作要求确认，并保存可以回滚的状态。

### Thinking 模式有成本

更长推理能够帮助数学、空间和多步任务，简单 OCR 与分类未必受益。长输出增加时延，也可能让模型围绕错误观察继续推理。按任务路由模式，并用外部检查确认关键视觉事实，会比统一拉长思考更稳定。

## 写在最后

Qwen-VL 的演进可以看作一次持续放宽接口的过程。固定图片先变成动态分辨率，帧序号随后接上真实时间，最终层视觉表示又扩展为多层视觉注入。模型获得结构化坐标与界面动作以后，视觉开始参与完整任务循环。

Qwen3.5 把这条路线并入主模型。VL 后缀消失，视觉能力成为默认配置。实际系统仍要处理像素、帧率、上下文、执行权限和回归测试。模型能看见多少，只决定起点。它能否在长任务里保留证据、修正动作并完成目标，还要看模型外面的那套工程。
