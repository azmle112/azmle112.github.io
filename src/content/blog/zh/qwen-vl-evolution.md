## 摘要

把五代 Qwen 多模态模型排在一起，可以看到视觉证据进入语言模型的路径一直在变。榜单名次只记录了变化后的系统结果。Qwen-VL 把一张固定尺寸图片压成 256 枚视觉 token，先建立一个可用且稳定的接口。Qwen2-VL 允许图片保留原始宽高比，让 token 数量随画面面积变化，又用多模态旋转位置编码统一文字、图像和视频。Qwen2.5-VL 继续修正时间轴，使不同帧率的视频能够按真实秒数定位，并在视觉编码器中用窗口注意力控制高分辨率成本。Qwen3-VL 通过 DeepStack 把多个视觉层级送入语言主干前部。Qwen3.5 随后取消独立的 VL 家族命名，把图像、视频、文本、工具使用和长上下文放进同一套预训练模型。

五代模型反复处理同一组工程约束。更多视觉细节会拉长序列，视频除了帧间先后还需要真实时间，视觉特征进入语言主干后又会改变吞吐和显存。每一代解决其中一部分，同时引入新的预算、位置和评测问题。

本文只采用论文、官方博客、官方仓库与官方模型卡。正文会区分论文给出的训练设计、公开配置可以直接核对的实现，以及根据这些材料做出的解释。表中 benchmark 是官方报告值，提示模板、输入预算、评审协议和数据版本并不完全一致。它们适合说明每一代优先解决什么，不能组成严格同条件排行榜。

## 第一章　Qwen-VL 先建立一条稳定的视觉通道

### 1.1 三个模块怎样接起来

[Qwen-VL 论文](https://arxiv.org/abs/2308.12966) 的结构相当清楚。视觉编码器采用 OpenCLIP 的 ViT-bigG，论文记为约 1.9B 参数。语言主干来自 Qwen-7B，论文参数表记为约 7.7B。两者之间是一层随机初始化的 cross-attention adapter，约 0.08B 参数。三部分合计约 9.6B。

输入图像经过视觉编码器后得到一串 patch 特征。adapter 持有一组可学习 query，用它们去读取视觉序列，再把结果投影到语言模型的隐藏维度。官方 `Qwen-VL-Chat` 配置可以核对到 `image_size` 为 448，`patch_size` 为 14，视觉宽度为 1664，视觉编码器有 48 层，输出维度为 4096。仓库中的视觉模块默认使用 256 个 query。

448 除以 14 得到 32，因此视觉塔在规则网格上先产生 32 乘 32 枚 patch，共 1024 个位置。adapter 最后只交付 256 枚视觉 token。压缩比并不能独立说明信息损失，因为每枚输出 token 都能通过 cross-attention 汇聚多个 patch。它仍然明确规定了一个固定容量。照片、文档和长截图面对同一扇门。

### 1.2 固定接口为什么在当时合理

2023 年的首要任务是让已经具备语言能力的 Qwen 稳定接收视觉证据。固定 256 枚 token 有几个直接好处。语言模型看到的图像段长度可预测，批处理和显存估算容易。多图对话仍能通过统一的图片起止标记组织。训练时也不必先解决任意宽高比和极长视觉序列带来的位置编码问题。

代价同样具体。任何图片都要进入固定画布。宽幅海报、竖直网页或密集表格会在缩放时牺牲小字。简单图片没有机会少用 token，复杂图片也没有机会多用。固定 query 负责从全图汇聚信息，局部文字和细小目标可能在压缩前已经难以辨认。

Qwen-VL 已经提供 grounding。模型用文本序列输出归一化到 `[0, 1000)` 的边界框坐标，让图像描述、问答与定位共享同一生成接口。这一步很重要，因为后来 GUI 操作、文档布局理解和空间推理都需要把语言落回二维位置。

### 1.3 三阶段训练怎样分工

论文把训练拆成视觉语言预训练、多任务预训练和监督微调。每一步开放的参数不同，输入分辨率和数据混合也不同。

| 阶段 | 主要输入 | 分辨率 | 参数更新 | 论文报告的数据规模与作用 |
| --- | --- | --- | --- | --- |
| 视觉语言预训练 | 图文对 | 224 | 冻结语言模型，训练视觉塔与 adapter | 原始约 50 亿图文对，经清洗后约 14 亿，建立视觉概念和语言对应 |
| 多任务预训练 | caption、VQA、OCR、grounding、纯文本 | 448 | 全参数训练 | 约 1970 万 caption、360 万 VQA、2480 万 OCR、各 870 万定位与带定位描述、780 万纯文本 |
| 监督微调 | 多轮对话与指令 | 448 | 冻结视觉塔，训练语言模型与 adapter | 约 35 万指令数据，形成聊天和指令遵循能力 |

第一阶段的清洗后图文对中，论文给出的英文比例为 77.3%，中文为 22.7%。第二阶段提高分辨率，又把 OCR、问答和定位任务放进同一训练混合。第三阶段冻结视觉塔，避免小规模指令数据大幅改写视觉表示。

这种课程安排揭示了初代模型的工程取舍。视觉塔需要先学会看，语言模型则先维持已有能力。等模态对齐稳定后再做全参数联合训练，最后用较少的对话数据塑造接口。后来几代训练规模急剧扩大，但先建立视觉表示、再扩展任务与上下文的节奏仍可辨认。

### 1.4 结果能说明什么

Qwen-VL 论文在 VQAv2 报告 79.5，在 TextVQA 报告 63.8，在 DocVQA 报告 65.1，在 ChartQA 报告 65.7。RefCOCO 验证集的定位准确率为 89.36。放回 2023 年的公开模型环境，这组结果说明一个通用语言模型经过视觉塔和轻量 adapter 后，已经能覆盖自然图像问答、文字读取、图表和区域定位。

它们无法证明固定 256 token 已经足够。OCR 和文档分数会同时受到输入缩放、视觉预训练数据、语言主干和解码格式影响。恰当的结论是 Qwen-VL 建立了可工作的基线，后续架构改动才有清楚的参照。

## 第二章　Qwen2-VL 让图片保留自己的形状

### 2.1 Naive Dynamic Resolution 改了什么

[Qwen2-VL 论文](https://arxiv.org/abs/2409.12191) 把固定视觉长度改成动态长度。图片先按尺寸约束缩放，使宽高都能被视觉 patch 和后续合并所要求的网格整除。长边、短边与总像素受到处理器预算限制，最终 token 数随缩放后的面积变化。

官方 7B 处理器配置给出的最小像素为 3136，等于 4 个 `28 × 28` 区域。最大像素为 12845056，等于 16384 个 `28 × 28` 区域。这里的 28 来自 14 像素 patch 与 2 乘 2 空间合并。配置表达的是理论处理范围。实际部署通常会主动降低 `max_pixels`，因为 16384 枚视觉 token 连同文本会显著占用显存和计算。

视觉编码器不再依赖固定绝对位置表。论文去掉绝对位置嵌入，在注意力中使用二维旋转位置编码。经过视觉塔后，相邻 `2 × 2` patch 通过 MLP 合并，空间高宽各缩小一半。若缩放后图像为 `H × W`，视觉内容 token 可近似写成下面的式子。

`N_visual = H / 28 × W / 28`

模型还会为图像段加入起止标记。论文用 224 乘 224 的例子说明，14 像素 patch 先产生 256 个 patch，2 乘 2 合并后留下 64 个视觉内容 token，加上起止标记得到 66。

### 2.2 动态分辨率首先解决的是信息分配

一张只含大号路标的图片不需要和一页密集合同使用相同视觉预算。动态分辨率让调用者能够按任务分配 token。OCR、表格和界面截图可以保留更多像素。普通照片可以主动缩小，换取吞吐。极端长图仍需要切片或降低尺寸，但它不再先被强制拉进正方形。

这种自由有明确成本。视觉 token 翻倍会增加后续语言层处理的序列长度。注意力显存、KV cache 和首 token 延迟都会受到影响。批处理里不同图片长度差异太大，还会造成 padding 或调度效率下降。动态分辨率把一个写死在架构里的常数，变成需要部署者管理的资源旋钮。

下面用处理器的 28 像素网格估算几种输入。实际处理器会按边界和整除规则调整尺寸，所以表中用于理解数量级。

| 缩放后尺寸 | 合并后的视觉内容 token | 适合观察的场景 | 主要成本 |
| --- | --- | --- | --- |
| 224 × 224 | 64 | 单物体、粗分类、低成本预览 | 小字和细节容易消失 |
| 448 × 448 | 256 | 普通照片、基础问答 | 与初代固定输出数量接近 |
| 896 × 896 | 1024 | 文档页、图表、界面 | 语言主干序列明显增长 |
| 1344 × 1792 | 3072 | 高密度页面、较大截图 | 首 token 延迟和显存压力很高 |

### 2.3 图像与视频怎样共用视觉塔

Qwen2-VL 用带时间深度的三维卷积处理视觉 patch。空间 patch 为 14 乘 14，时间 patch 深度为 2。视频可以把相邻两帧作为一个时间单元。静态图片没有第二帧，论文采用复制成两张相同帧的做法，使图像和视频能够通过同一个 patch embedding。

统一入口减少了两套编码器之间的割裂。图片相当于没有发生变化的短视频片段，视频则是带连续时间单元的视觉网格。后面的空间合并规则保持一致。

这套统一也带来边界。复制图片并不会凭空产生时间信息，它只是满足卷积接口。视频抽帧仍决定模型看见哪些瞬间。若关键动作落在采样间隙，后面的时空位置编码无法恢复缺失内容。

### 2.4 M-RoPE 怎样表示三种坐标

语言序列只需要一维顺序。图片需要高度和宽度。视频还需要时间。Qwen2-VL 的多模态旋转位置编码把位置维度分给时间、高度和宽度三个方向。

文本 token 在三个方向使用同一位置编号，因此仍表现为普通一维顺序。图片内的 token 共享一个时间编号，高度与宽度按二维网格变化。视频 token 的时间编号随时间单元递增，高度与宽度继续表示帧内位置。不同模态段之后的文字从前面使用过的位置继续编号。

论文所解决的是异构坐标如何进入同一自回归序列。它还没有让时间编号严格对应现实秒数。若两个视频都抽取相同帧数，原视频时长不同却可能得到相近的位置跨度。这个缺口交给了下一代。

### 2.5 训练和结果需要怎样读

Qwen2-VL 论文报告累计使用约 1.4 万亿 token，并说明其中包含视觉 token。训练视频按每秒 2 帧采样，每个视频的视觉 token 上限为 16384。损失只计算文本 token，图像与视频 token 提供条件，不直接承担下一 token 预测目标。

72B 模型在论文表中取得 DocVQA 96.5、TextVQA 85.5、OCRBench 877、MMMU 64.5。Video-MME 无字幕和有字幕设置分别为 71.2 与 77.8。AITZ 为 72.1。数字横跨文档、通识视觉问答、视频和手机界面操作，说明动态分辨率没有停留在输入预处理层，它支持了更广的任务组合。

Qwen2.5-VL 论文回顾前代时把 Qwen2-VL 的预训练规模记为 1.2 万亿，而 Qwen2-VL 自己的论文写约 1.4 万亿。两篇一手材料的口径不一致。合理处理方式是保留各自原文，不把差额擅自解释为清洗、去重或 token 统计方法的变化。

## 第三章　Qwen2.5-VL 把时间和高分辨率成本纳入设计

### 3.1 动态帧率修正了什么

[Qwen2.5-VL 论文](https://arxiv.org/abs/2502.13923) 允许视频用不同帧率采样，例如每秒 0.5、1 或 2 帧。时间位置编号不再只按抽到的帧顺序增加，而会依据帧的时间戳与 `tokens_per_second` 对齐。官方 7B 配置把这一值设为 2。

假设一段 20 秒视频采用每秒 0.5 帧，另一段采用每秒 2 帧。两者相邻采样帧在现实中的间隔分别为 2 秒和 0.5 秒。若都简单加一，模型看到的位置间隔相同。绝对时间对齐会让前者跨过更大的时间位置距离，后者使用更密的刻度。模型因而更容易学习秒级定位，也能在低帧率长视频和高帧率短动作之间保持相近的时间语义。

### 3.2 窗口注意力为何关键

动态分辨率让视觉 token 数可能达到数千甚至上万。若视觉塔每一层都做全局自注意力，成本会随 token 数平方增长。Qwen2.5-VL 在大多数视觉层采用窗口注意力，只让局部窗口内的 patch 相互作用，并在少数层保留全局注意力。

官方 7B 配置显示视觉编码器有 32 层，隐藏维度 1280，16 个注意力头，窗口大小 112。全局注意力层索引为 7、15、23、31。按从零开始编号，它们每隔八层出现一次。其余层用局部窗口处理细节，四个全局层负责跨窗口交换信息。

窗口注意力把高分辨率视觉编码的主要计算限制在局部，但全局层仍可能成为长视觉序列的峰值。语言主干接收合并后的全部视觉 token，也继续承担长序列成本。因此这是一种成本重分配，并未让分辨率变得无代价。

### 3.3 文档、界面和物体定位怎样进入统一输出

Qwen2.5-VL 强化了两类结构化输出。文档解析需要同时读取文字、恢复阅读顺序、理解表格与布局。GUI 操作需要识别界面元素，再输出可执行动作及位置。两者都依赖精细视觉输入，也依赖语言模型生成稳定格式。

模型继续使用归一化坐标表示位置。对界面任务而言，一个动作可以被写成动作类型、目标坐标和必要参数。对文档而言，模型可以生成文本、布局框或结构化标记。视觉理解和行动接口因此共享自回归输出空间。

这并不等同于浏览器或手机自动执行安全可靠。模型分数通常在固定环境、固定动作空间和可重复任务上测得。真实界面会出现弹窗、加载延迟、权限确认和不可逆操作。执行系统仍需截图更新、状态校验、动作白名单和人工确认。

### 3.4 三段预训练把规模推到 4.1 万亿 token

论文把 Qwen2.5-VL 的预训练分成三个阶段，总计 4.1 万亿 token。这里的 token 同样包含多模态输入的统计口径。

| 阶段 | token 规模 | 最大序列长度 | 主要训练重点 |
| --- | --- | --- | --- |
| 第一阶段 | 1.5 万亿 | 8192 | 建立视觉语言对齐，覆盖图像与基础文本能力 |
| 第二阶段 | 2.0 万亿 | 8192 | 扩展数据和任务范围，加强文档、图表、视频与多图理解 |
| 第三阶段 | 0.6 万亿 | 32768 | 长序列、多图与长视频，继续联合优化 |

从 8192 提高到 32768 的阶段只占总 token 一部分，这符合长上下文训练的常见成本约束。短序列负责大量基础学习，较昂贵的长序列在后段集中加入。公开材料没有给出足以复原全部采样比例的数据配方，不能从总量倒推出每类任务的精确占比。

### 3.5 官方结果与可比性边界

Qwen2.5-VL-72B 在论文中报告 MMMU 70.2、MathVista 74.8、CC-OCR 79.8、CountBench 93.6。ScreenSpot Pro 为 43.6，AndroidWorld 为 35.0。它们分别对应通用多学科视觉理解、视觉数学、综合 OCR、计数与界面操作。

模型从 Qwen2-VL 到 Qwen2.5-VL 的提升同时来自架构、训练数据、训练规模、语言主干和任务后训练。窗口注意力或动态帧率无法独自解释所有增益。论文消融可以支持局部设计判断，跨代总分仍应理解为整套系统的结果。

## 第四章　Qwen3-VL 把视觉信息送进语言主干更深处

### 4.1 视觉塔初始化与尺寸变化

[Qwen3-VL 论文](https://arxiv.org/abs/2511.21631) 采用 SigLIP 2 初始化视觉编码器。较大模型默认使用 SigLIP2-SO-400M，2B 与 4B 版本使用 SigLIP2-Large。官方 8B 配置显示视觉塔共有 27 层，隐藏维度 1152，16 个注意力头，空间 patch 为 16，时间 patch 深度为 2，空间合并仍为 2。

这意味着视觉网格的基本单位从前两代常见的 14 像素 patch 改为 16 像素 patch。合并后一枚视觉 token 大致覆盖 `32 × 32` 像素区域。官方预处理器配置允许的最短边总像素为 65536，也就是 256 的平方，最长边总像素为 16777216，也就是 4096 的平方。它仍是一段很宽的理论范围，实际限制需要结合模型上下文与显存设置。

视觉塔更换初始化来源时，跨代差异不宜只归因于后面的 DeepStack。预训练视觉特征、patch 大小、数据与语言主干全部发生变化。准确说法是 DeepStack 定义了一条新的多层注入路径，整代性能由多项变化共同形成。

### 4.2 DeepStack 解决单次注入的损耗

此前模型通常把视觉编码器最后一层经过 merger 的结果放到语言序列中，之后由语言层逐步处理。视觉塔浅层更擅长保留局部边缘和纹理，深层更偏向高层语义。只交付末层表示，会让语言主干主要依赖一次压缩后的视觉摘要。

DeepStack 从视觉编码器的三个中间层取出特征，各自经过专用 merger，再分别加到语言模型最前面的三个隐藏层。官方 8B 配置给出的视觉索引为 8、16、24。初始视觉序列仍然存在，中间特征以加法注入，不额外占用上下文 token。

### 4.3 交错 M-RoPE 改变频率分配

官方 8B 配置启用 `mrope_interleaved`，位置分段为 24、20、20。早期 M-RoPE 可以把时间、高度和宽度分配到连续的旋转频率区间。交错形式把三个方向分散到低频与高频维度中，避免某一坐标方向只占据单一频率带。

直观上，低频适合表示大范围位置变化，高频对细小位移更敏感。让时间、高度和宽度都接触多种频率，有助于同时表达全局与局部关系。这种解释来自 RoPE 的频率结构。具体收益仍应以论文消融为准，不能仅凭配置推断某类空间错误已经消失。

### 4.4 视频时间戳从位置变成可读文本

Qwen3-VL 在视频序列中使用文本时间戳，例如 `<3.0 seconds>`。官方处理器也支持时分秒格式。模型能够在生成答案时直接引用这些标记，训练数据中的事件描述和时间定位拥有统一的文本锚点。

这与 Qwen2.5-VL 的绝对时间位置各有侧重。旋转位置编码把时间写进隐藏表示，文本时间戳把时间写进可见序列。后者更容易被模型复制、比较和输出，也让调试者看到帧对应哪个时刻。代价是时间戳本身占用 token，格式与采样元数据必须正确。

### 4.5 四阶段预训练怎样扩到 256K

Qwen3-VL 论文把预训练列为四个阶段。前两阶段建立并扩大视觉语言能力，后两阶段延长上下文。

| 阶段 | 可训练部分 | 训练 token | 最大序列长度 | 作用 |
| --- | --- | --- | --- | --- |
| S0 | 仅视觉 merger | 670 亿 | 8192 | 让视觉表示先适配语言主干 |
| S1 | 全参数 | 约 1 万亿 | 8192 | 联合训练基础多模态能力 |
| S2 | 全参数 | 约 1 万亿 | 32768 | 加入更长文档、多图和视频序列 |
| S3 | 全参数 | 1000 亿 | 262144 | 建立原生 256K 长上下文 |

官方模型卡把 262144 作为原生上下文长度。它允许长视频、整份文档和大量图片进入同一会话，但输入上限仍需分给文本、视觉 token、时间戳和将要生成的答案。256K 是所有输入共享的总账本，视频只能使用其中一部分。

### 4.6 大规模视频评测怎样设置

Qwen3-VL 论文的视频评测最多使用 2048 帧，视觉 token 上限为 224K。VideoMMMU 和 MMVU 使用每帧 768 token，其他视频基准使用每帧 640 token。Charades-STA 采用 4 fps，其他列出的评测多采用 2 fps。

这些数字对解读长视频成绩很关键。不同模型可能拥有不同最大帧数和 token 预算。论文同时列出外部模型的帧预算，例如 Gemini 使用 512 帧，GPT-5 使用 256 帧，Claude 使用 100 帧，并明确提醒比较公平性受限。若忽略输入预算，只看最终分数，很容易把更多视觉证据带来的收益全部归给推理能力。

### 4.7 Thinking 与 Instruct 应怎样区分

Qwen3-VL 同时提供 Instruct 和 Thinking 取向的模型。Thinking 版本允许生成更长的中间推理文本，适合视觉数学、复杂空间关系和多步问题。Instruct 版本更偏向直接响应与通用交互。

两者的选择首先取决于任务和延迟。简单 OCR 或界面元素定位通常不需要很长输出。多页文档比较或复杂几何题可能从更充分的推理过程获益。无论使用哪一种，模型都受输入分辨率、帧采样和证据覆盖限制。生成更多文字无法补回根本没有输入的细节。

论文中的 235B-A22B 模型在 MMLongBench-Doc Instruct 取得 57.0，Thinking 取得 56.2。MuirBench 的 Thinking 结果为 80.1。EmbSpatial 为 84.3，RefSpatial 为 69.9，RoboSpatial-Home 为 73.9。这里出现了一个有用提醒。Thinking 并不会在每个任务上都高于 Instruct，任务协议和输出形式会影响它是否合适。

## 第五章　Qwen3.5 把视觉变成主模型的默认能力

### 5.1 VL 后缀为什么消失

[Qwen3.5 官方博客](https://qwen.ai/blog?id=qwen3.5) 把系列描述为原生多模态模型。正式权重名称不再区分一个独立 VL 分支。图像和视频处理器随模型一起发布，聊天模板能够组织文本、图片、视频与工具调用。

名称变化对应训练产品形态的变化。此前用户需要在 Qwen 语言模型与 Qwen-VL 视觉语言模型之间选择。Qwen3.5 默认把两类输入放入同一模型家族。统一并不意味着图像与文本在底层完全采用相同编码。公开配置仍有独立视觉编码器和 merger。它意味着预训练目标、权重发布和使用接口把多模态当成主线能力。

### 5.2 混合注意力怎样降低长上下文成本

Qwen3.5 的语言主干把 Gated DeltaNet 线性注意力层与标准 Gated Attention 层交替使用。官方 397B-A17B 模型卡描述的节奏是三层 Gated DeltaNet 后接一层 Gated Attention，共重复 15 次，得到 60 层。27B 公开配置也呈现三层线性注意力加一层全注意力的重复结构，共 64 层。

线性注意力用递推状态汇总历史，避免每一层都对完整序列计算二次注意力。标准全注意力层定期让 token 直接访问长距离位置，补充精确检索能力。三比一的节奏把大部分层放在更适合长序列的计算路径上，又保留跨段关联的锚点。

### 5.3 稠密与 MoE 版本怎样读

Qwen3.5 同时覆盖小型稠密模型、大型稠密模型和混合专家模型。MoE 名称中的前一个数字表示总参数量，A 后面的数字表示单次前向大致激活的参数量。例如 397B-A17B 拥有约 397B 总参数，每个 token 激活约 17B。

| 模型 | 结构类型 | 总参数或规模标记 | 每 token 激活规模 | 更现实的部署位置 |
| --- | --- | --- | --- | --- |
| Qwen3.5-0.8B 至 9B | 稠密 | 0.8B 至 9B | 与总参数接近 | 边缘设备、单卡、低成本服务 |
| Qwen3.5-27B | 稠密 | 27B | 27B | 高显存单机或多卡张量并行 |
| Qwen3.5-35B-A3B | MoE | 35B | 约 3B | 需要容纳专家权重，单 token 计算较低 |
| Qwen3.5-122B-A10B | MoE | 122B | 约 10B | 多卡服务，显存与通信仍显著 |
| Qwen3.5-397B-A17B | MoE | 397B | 约 17B | 数据中心多卡或托管 API |

激活参数少不等于显存只需容纳激活部分。全部专家权重通常仍要驻留或被高效调度，路由还会引入通信与负载均衡问题。量化能够降低权重显存，视觉编码器、KV cache、激活和运行时开销仍要单独计算。

### 5.4 公开配置透露了哪些连续与变化

Qwen3.5-27B 的视觉配置与 Qwen3-VL-8B 有明显连续性。两者视觉塔都为 27 层、隐藏维度 1152、16 个头、16 像素空间 patch、时间深度 2 和 2 倍空间合并。Qwen3.5-27B 配置中的 `deepstack_visual_indexes` 是空列表。至少对这一公开检查点，不能沿用 Qwen3-VL 必然启用三个 DeepStack 注入点的说法。

语言侧变化更大。27B 有 64 层、隐藏维度 5120，并以三层线性注意力和一层全注意力循环。全注意力使用 24 个 query 头和 4 个 KV 头，head dimension 为 256。线性层另有 16 个 key 头与 48 个 value 头。词表大小为 248320，原生最大位置为 262144，交错多模态位置分段为 11、11、10。

这些数字来自公开配置，不代表所有 Qwen3.5 规模完全相同。MoE 版本还包含专家数量、路由 top-k 和共享专家等参数。397B-A17B 模型卡给出 512 个专家，每个 token 路由到 10 个专家，并另有 1 个共享专家。

### 5.5 训练规模应保留怎样的证据边界

官方材料把 Qwen3.5 预训练描述为数十万亿多模态 token，但没有给出一个足以逐项审计的精确总数和完整数据配方。本文只保留这个有来源的量级。能够确认的事实是，训练同时覆盖文本、图像、视频和面向 Agent 的交互数据，规模显著高于前代论文披露的数万亿量级。

数据规模本身也不等于有效监督。图文配对质量、视频时间覆盖、文档去重、OCR 噪声、动作轨迹成功率和语言分布都会影响最终能力。没有公开采样权重时，不能用总 token 推断某一任务究竟得到多少训练份额。

### 5.6 官方结果反映了哪些重点

397B-A17B 模型卡报告 MMMU 85.0、MMMU-Pro 79.0、MathVision 88.6、MathVista 90.3、OmniDocBench 1.5 为 90.8、CC-OCR 为 82.0。27B 模型卡报告 MMMU 82.3、MathVision 86.0、VideoMME 无字幕 82.8、有字幕 87.0、ScreenSpot Pro 70.3、OSWorld-Verified 56.2、AndroidWorld 64.2。

这组结果覆盖视觉知识、数学、文档、OCR、视频和计算机操作。Qwen3.5 的定位已经超出传统图片问答。模型需要读屏、保持长任务状态、调用工具并根据新观察继续操作。

跨代比较仍需注意版本和预算。ScreenSpot Pro 的输入分辨率、坐标输出形式、提示和评测脚本可能变化。VideoMME 是否使用字幕会产生显著差异。模型卡数字适合确认官方宣称的能力范围，复现时还要锁定处理器、聊天模板、解码参数和数据集提交版本。

## 第六章　五代架构改了什么

### 6.1 从固定瓶颈到可管理预算

初代把每张图片压成固定 256 枚视觉 token。Qwen2-VL 之后，视觉 token 成为输入面积的函数。这个变化提高了细节上限，也把责任交给使用者。模型不再替你决定每张图只能占多少位置，服务端必须为不同任务制定像素预算。

Qwen3-VL 的 DeepStack 提供另一条思路。多个视觉层级直接注入已有语言隐藏状态，序列 token 数保持不变。Qwen3.5 又从语言主干入手，用混合注意力降低长序列层层做全局计算的压力。五代模型依次改动了压缩接口、输入长度、隐藏层信息通路和序列计算方式。

| 维度 | Qwen-VL | Qwen2-VL | Qwen2.5-VL | Qwen3-VL | Qwen3.5 |
| --- | --- | --- | --- | --- | --- |
| 图像尺寸 | 固定画布 | 动态分辨率 | 动态分辨率 | 动态分辨率 | 动态分辨率 |
| 视觉长度 | 固定 256 | 随面积变化 | 随面积变化 | 随面积变化 | 随面积变化 |
| 图像视频入口 | 图像为主 | Conv3D 统一 | Conv3D 与动态帧率 | 视频时间戳与统一处理 | 统一多模态模型接口 |
| 位置机制 | 视觉塔固定位置与语言一维位置 | 二维 RoPE 与 M-RoPE | 绝对时间对齐 | 交错 M-RoPE | 交错 M-RoPE |
| 视觉塔计算 | 全局注意力 | 动态网格 | 窗口为主，少量全局 | SigLIP 2 初始化与 DeepStack | 延续视觉前端，公开 27B 未启用 DeepStack 索引 |
| 语言主干 | Qwen-7B | Qwen2 | Qwen2.5 | Qwen3 稠密或 MoE | DeltaNet 与全注意力混合，稠密或 MoE |
| 原生上下文 | 短上下文时代 | 32K 配置 | 32K 训练阶段 | 256K | 256K，可配置扩展约 1M |

### 6.2 时间经历了三次不同修正

Qwen2-VL 先让视频 token 拥有时间维度。Qwen2.5-VL 再让这个维度对应现实时间间隔。Qwen3-VL 把时间戳放进可读文本。三步分别解决有无时间坐标、坐标是否等距于秒数、模型能否直接引用时间。

三者仍依赖正确的媒体元数据。容器时间戳异常、可变帧率处理错误或抽帧程序用索引冒充时间，都会把错误送进模型。视频理解系统需要保存原始时间基、抽帧时间和展示时间之间的映射，不能只传一个帧列表。

### 6.3 多模态统一并没有消除模态差异

图像仍先经过视觉塔，文本仍经过词嵌入。视觉 token 数由像素决定，文本 token 数由分词决定。视频还要处理帧采样和时间戳。统一模型解决的是联合训练、共同上下文和统一输出，不会让各模态的数据成本与误差来源自动相同。

这一点对系统设计很实用。OCR 错误要从分辨率、图像质量和文字方向检查。视频漏事件要先看采样。工具调用失败要区分模型动作、执行器和新状态观察。把所有问题归为模型没理解，会错过最容易修复的环节。

## 第七章　视觉 token 预算怎样算

### 7.1 图片预算

Qwen2-VL 与 Qwen2.5-VL 使用 14 像素 patch 和 2 乘 2 空间合并，合并后每枚视觉内容 token 约覆盖 28 乘 28 像素。Qwen3-VL 的公开 8B 配置改为 16 像素 patch，合并后约覆盖 32 乘 32 像素。边界处还要满足整除与处理器缩放规则。

对于 28 像素网格，预算 1024 token 大致对应 802816 个像素，可看作接近 896 乘 896 的正方形。预算 4096 token 则接近 1792 乘 1792。实际长宽可以不同，只要面积和网格约束相近。

### 7.2 视频预算

视频 token 大致由采样帧数、每帧缩放后面积、时间 patch 合并和空间合并共同决定。提高 fps 与提高每帧分辨率都会增加视觉序列。两者对任务的贡献不同。快速动作更需要帧密度，小字和界面状态更需要单帧像素。

### 7.3 一套可执行的预算流程

先确定任务最小证据。若问题只问发票总额，重点是文字清晰度。若问题问球何时越过门线，重点是时间采样。接着给视觉输入设硬上限，预留提示、工具结果和答案空间。再用少量代表样本逐步提高分辨率或 fps，观察准确率和延迟曲线。最后锁定处理器参数，并把它们和模型版本一起记录。

预算实验至少记录缩放后宽高、实际帧数、实际视觉 token、文本 token、首 token 延迟、峰值显存和任务正确率。只记录原始图片尺寸没有意义，因为处理器可能在进入模型前再次缩放。

## 第八章　部署时怎样选模型与设置

### 8.1 先按证据需求选代际

如果项目已有 Qwen-VL，且输入都是普通图片、上下文很短，升级收益主要来自更好的视觉主干和数据。若任务依赖文档、长截图或任意宽高比，Qwen2-VL 之后的动态分辨率更关键。若需要长视频时间定位、复杂文档或 GUI，Qwen2.5-VL 是更清楚的能力分界。若需要长上下文、空间推理和更深视觉注入，Qwen3-VL 更合适。若希望用一个统一模型同时处理文字、视觉、工具和长任务，Qwen3.5 更贴近这一系统形态。

| 需求 | 起步选择 | 需要重点验证的配置 |
| --- | --- | --- |
| 低成本图片问答 | Qwen2.5-VL 3B 或 Qwen3-VL 2B、4B | 最小像素、量化、OCR 细节损失 |
| 文档与图表 | Qwen2.5-VL 7B、32B 或 Qwen3-VL 8B | 最大像素、分页策略、结构化输出 |
| 长视频 | Qwen3-VL 或 Qwen3.5 | fps、每帧 token、总帧数、时间戳正确性 |
| GUI Agent | Qwen2.5-VL、Qwen3-VL 或 Qwen3.5 | 截图更新、坐标映射、动作安全和恢复 |
| 统一文本视觉服务 | Qwen3.5 | 混合注意力内核、上下文预算、工具协议 |
| 数据中心高精度 | Qwen3.5 大型 MoE | 专家权重显存、并行通信、路由负载 |

### 8.2 模型大小以外还有哪些成本

同一个 7B 模型，224 乘 224 图片和多页高分辨率文档的运行成本相差很大。视觉塔前向、视觉 token 进入语言主干后的 prefill、生成时 KV cache、批处理 padding 和视频解码都要算入端到端延迟。

MoE 模型还要区分计算量和驻留权重。A3B 或 A17B 描述激活规模，服务端仍需存放大量专家。多卡环境中的专家并行会受互联带宽影响。小批量请求若路由分散，硬件利用率可能低于理论值。

量化需要分别验证文字、视觉和动作输出。OCR 常对细微 logit 变化敏感，坐标生成的一个 token 错误可能把点击位置移到相邻控件。平均 benchmark 变化很小，不代表关键业务错误率同样稳定。

### 8.3 处理器版本为什么必须锁定

动态分辨率、视频抽帧、时间戳文本和聊天模板大多由处理器代码完成。模型权重不变，升级 `transformers` 或官方仓库也可能改变默认帧率、像素上下限、时间戳格式或图片起止标记。

可复现记录应包括模型仓库 revision、处理器 revision、推理框架版本、聊天模板、`min_pixels`、`max_pixels`、视频 fps、最大帧数、最大生成长度和精度类型。视频还应保存解码库与时间基处理方式。这样才能判断结果变化来自权重、输入还是运行时。

### 8.4 GUI 与工具调用的安全边界

界面 benchmark 通常允许模型在模拟或受控环境里执行点击、输入和滚动。真实系统包含支付、删除、发送和权限修改等不可逆动作。部署时应把视觉模型放在受约束执行器后面。

执行器可以检查动作类型和目标区域，对高风险动作要求确认。每次动作后重新截图，验证页面是否达到预期状态。若目标控件移动或弹窗遮挡，旧坐标应立即失效。任务日志需保留模型观察、动作、执行结果和新状态，便于审计。

模型输出坐标还要映射回原始屏幕。输入截图可能经过缩放和 padding，模型坐标多为归一化值。映射程序应使用处理器实际变换后的尺寸，处理设备像素比、滚动偏移和窗口边框。坐标变换错误经常被误判为视觉定位失败。

## 第九章　怎样公平地评估一套多模态系统

### 9.1 固定输入预算再谈模型差异

比较两个模型时，应先固定图片像素、视频帧数、每帧 token 和总上下文。若一方看到 2048 帧，另一方只看到 100 帧，最终差异同时包含证据数量和模型能力。可以另做各自最佳预算实验，但需要与等预算结果分开展示。

文档任务也一样。允许一方读取完整 4K 页面，另一方只用 896 像素输入，OCR 对比没有解释力。动态分辨率时代，预处理参数已经属于模型设置的一部分。

### 9.2 分解错误比总分更有用

多模态错误至少可以分为感知、选择、时序、推理、格式和执行。感知错误是字或目标没有看清。选择错误是关键帧没被抽到。时序错误是事件顺序或时间戳错。推理错误发生在证据已经可见时。格式错误是 JSON、坐标或工具参数不合法。执行错误来自浏览器、手机或外部 API。

分解后才能决定改哪里。提高图片分辨率不会修复工具参数 schema。增加推理文字也不会修复漏帧。换更大模型或许能掩盖一部分问题，成本却可能远高于修复预处理器。

### 9.3 benchmark 分数旁边应该记录什么

| 记录项 | 为什么需要 |
| --- | --- |
| 模型与处理器 revision | 权重和输入逻辑可能独立变化 |
| 输入像素与视觉 token | 动态分辨率直接改变证据量 |
| 视频 fps、帧数和时间戳 | 决定事件覆盖与时间定位 |
| 提示模板与输出约束 | 影响格式、工具调用和评审 |
| 是否使用字幕或 OCR 辅助 | 可能显著改变视频和文档分数 |
| 解码参数与最大输出长度 | 影响长答案和结构化输出 |
| 评审器与数据集版本 | 自动评审和题目修订会改变结果 |
| 延迟、吞吐和峰值显存 | 判断方案能否在目标硬件运行 |

### 9.4 复现官方分数时的现实边界

论文常使用内部推理栈、特定系统提示和尚未完整公开的数据处理脚本。模型卡更新也可能修正分数或推荐设置。开源权重让架构和基本能力可检查，却未必能一键重现每张表。

可行做法是先复现官方最接近的配置，再做本地等预算基线。若结果不同，优先检查图像缩放、视频后端、聊天模板和答案解析。报告差异时给出完整配置，并把无法确认的内部步骤标出来。

## 第十章　仍然没有解决的问题

### 10.1 更多像素会把噪声一起带进来

高分辨率能保留小字，也会带来背景纹理、压缩噪声和无关界面区域。语言主干需要在更长序列中寻找证据。若任务只关心局部区域，全图高分辨率可能比先定位再放大更昂贵。

后续系统可以把低分辨率全局观察与局部裁剪结合。第一遍确定候选区域，第二遍只提高相关位置的像素预算。评价时应把额外视觉调用和总 token 一并计入。

### 10.2 长视频的核心仍是选择

256K 上下文和混合注意力提高了可容纳长度，现实视频仍可能长达数小时。均匀抽帧会浪费静止段，也会漏掉短事件。字幕、镜头边界、音频变化和低成本运动信号可以帮助选择候选片段。

选择器一旦漏掉关键证据，主模型很难知道自己漏看了什么。更可靠的系统应允许回看，保存时间索引，并在答案不确定时请求更密采样。最终报告需要区分一次输入结果与经过外部检索的视频系统结果。

### 10.3 时间理解仍受数据和协议限制

显式时间戳让秒数可见，却不能自动解决因果、持续时间和并发事件。模型可能正确复述帧时间，仍误判动作起止。训练数据中的时间标注粒度、边界噪声和问题形式都会影响能力。

评测应分别考察事件检索、起止定位、顺序判断、持续时间比较和跨镜头因果。把它们合成一个视频总分，会隐藏模型究竟在哪一类时间关系上失败。

### 10.4 文档理解还需要版面与来源忠实度

把一页文档读成文本只是第一步。表格跨页、脚注引用、双栏阅读顺序、印章遮挡和手写批注都可能改变含义。生成式输出还可能补全不存在的字句。

高风险文档系统应保留字符或字段对应的页面与区域，允许用户回看原图。结构化抽取需要 schema 校验、数值核算和空值策略。模型不确定时应返回无法辨认，不能用流畅语言掩盖证据缺失。

### 10.5 Agent 能力需要外部状态闭环

静态截图只提供一个时刻。工具动作改变页面后，模型必须重新观察。网络延迟、异步加载和权限弹窗会让动作结果偏离预期。长任务还会遇到历史上下文膨胀和目标漂移。

可靠 Agent 需要状态摘要、关键截图保留、动作前后断言、超时与回滚。模型负责提出下一步，执行框架负责限制权限并确认现实状态。单次界面 benchmark 很难覆盖这些工程条件。

### 10.6 开放权重仍不等于完全开放训练

官方论文提供架构、阶段规模和大量结果，完整数据清单、清洗规则、采样权重和训练基础设施仍未全部公开。研究者能够分析配置和推理行为，却无法逐项重建训练分布。

因此，跨代叙事应把可以核对的设计与无法核对的原因分开。某项能力提升可能来自视觉塔、语言主干、数据或后训练的共同作用。缺少消融时，最稳妥的结论只到系统层面。

## 第十一章　一条更实用的阅读方法

读新的多模态模型报告时，可以先看处理器配置。它会告诉你模型实际吃进去多少像素、多少帧以及怎样写时间戳。再看视觉配置，确认 patch 大小、空间合并、窗口或全局层、视觉注入位置。之后看语言配置，确认上下文、注意力类型、KV 头和 MoE 路由。最后回到训练表和 benchmark，核对数据规模与输入预算。

这个顺序能避开两种常见误读。第一种只看模型总参数，忽略视觉序列让同一模型出现巨大成本差异。第二种只看最终分数，把预处理和帧预算的变化当成架构本身的能力。

| 阅读对象 | 先核对的问题 | 能避免的误判 |
| --- | --- | --- |
| 处理器配置 | 图片怎样缩放，视频怎样采样 | 把输入差异算成模型差异 |
| 视觉配置 | patch、合并、窗口和注入点是什么 | 只凭模型名字推断视觉结构 |
| 语言配置 | 上下文与注意力怎样组织 | 把理论长度当成免费容量 |
| 训练说明 | token 口径和阶段是否一致 | 擅自拼接不一致的训练总量 |
| benchmark 协议 | 帧数、字幕、提示和评审是否一致 | 把非同条件结果排成排行榜 |

## 第十二章　把三类真实输入沿五代模型走一遍

架构名称容易让人失去尺度感。下面选一页论文、一段十分钟视频和一次界面操作，把处理器在实际输入上的工作展开。数字用于估算输入量，具体版本仍以处理器输出为准。

### 12.1 一页双栏论文怎样进入模型

假设原始页面为 2480 乘 3508 像素，正文双栏，夹有一张图和一个小表格。Qwen-VL 会把它送进固定 448 乘 448 画布。页面宽高比约为 0.71，若保持比例并补边，正文有效宽度只有三百多像素。原来十几个像素高的字可能只剩两三个像素。视觉塔后面即使保留 256 枚汇聚 token，也无法重新创造缩放时丢掉的笔画。

Qwen2-VL 可以保持长宽比，并按 `max_pixels` 决定缩放程度。若将页面处理成 896 乘 1260 左右，按 28 像素合并网格估算，视觉内容 token 约为 32 乘 45，也就是 1440。文字拥有更高采样密度，序列却比 448 方图的 256 token 长出五倍以上。若一次放入二十页，同样设置会产生约 28800 枚视觉 token，还没有计算页面标记、问题和答案。

Qwen2.5-VL 的窗口注意力主要降低视觉塔内部编码这 1440 个位置的成本。视觉 token 进入语言模型后依然占据上下文。页面很多时，合理策略通常是先做分页检索，找出候选页，再把少量高分辨率页面交给模型。若任务需要跨页表格或脚注回指，检索结果还要保留相邻页和版面坐标。

Qwen3-VL 的 DeepStack 能把较早视觉层的局部信息送进语言主干。这对小字、线条和表格边界可能有帮助，前提仍是输入像素足够。视觉特征的深层注入无法恢复已经缩成同色块的字符。Qwen3.5 的混合注意力更适合把多页视觉 token、检索片段和较长问题放在同一上下文中，它也不会免除分页和证据定位。

文档系统因此需要两套坐标。第一套是原始 PDF 页面坐标，供引用和回看。第二套是处理器缩放后的视觉坐标，供模型定位。若中间有 padding、裁剪或拼图，还需要保存完整仿射映射。只保留模型给出的归一化框，后续很难准确标回原文。

### 12.2 文档问题还要区分读取与推断

问一张表里的数值，首先是读取。问两列增长率为何不同，还需要计算和解释。模型若把一个数字读错，后面的推理即使形式完整也会得到错误结论。评测时应把字符识别、单元格归属、跨页关联和数值推理拆开。

可以让模型在答案旁返回页码和框，但框本身也可能生成错误。更稳妥的做法是用模型框回原图裁剪，再做一次局部确认。金额、日期和剂量等高风险字段还可与规则或计算器交叉检查。多模态模型负责理解版面与上下文，确定性程序负责格式和算术。

Qwen 系列的生成式接口很灵活，可以输出 Markdown、JSON 或带框文本。生产系统不应假设每次输出都满足 schema。应先解析，再校验字段类型、范围和必填项。失败时请求修复格式，仍失败则停止自动执行。

### 12.3 十分钟视频的 token 为什么很快变大

十分钟等于六百秒。按 2 fps 均匀采样会得到 1200 帧。Qwen2-VL 与 Qwen2.5-VL 的时间 patch 深度为 2，因此大致形成 600 个时间单元。若每帧都按 448 乘 448 处理，一个时间单元在空间合并后约有 16 乘 16 个位置，也就是 256 枚视觉 token。粗略总量达到 153600，尚未计入特殊 token 和文本。

这个估算解释了论文为何需要视觉 token 上限，也解释了长视频不能只靠提高上下文长度。若把每帧缩到 224 乘 224，单个时间单元约有 64 token，总量降到 38400。它能覆盖全程，却可能看不清屏幕小字。若降到 0.5 fps，帧数再减少四倍，但一秒内发生的短动作更容易消失。

Qwen3-VL 使用 16 像素 patch 和 2 乘 2 合并。同样 448 方图每个时间单元约有 14 乘 14 个空间位置，即 196 token。1200 帧对应约 117600 token。实际处理器会按视频总预算调整每帧像素，论文评测还会设置每帧 token 和总 token 上限，所以不能把这组手算值当作官方默认输出。

| 十分钟视频设置 | 粗略帧数 | 每时间单元空间 token | 粗略视觉 token | 更容易保留的信息 |
| --- | --- | --- | --- | --- |
| Qwen2 系，2 fps，448 方图 | 1200 | 256 | 153600 | 动作覆盖与中等尺寸细节 |
| Qwen2 系，2 fps，224 方图 | 1200 | 64 | 38400 | 动作覆盖，文字细节较弱 |
| Qwen2 系，0.5 fps，448 方图 | 300 | 256 | 38400 | 稀疏时刻的高分辨率细节 |
| Qwen3 系，2 fps，448 方图 | 1200 | 196 | 117600 | 较密时间覆盖与中等细节 |

表中两种 38400 token 设置很能说明问题。总预算相同，一个把 token 花在更多低分辨率帧上，另一个花在更少高分辨率帧上。它们看到的证据不同。视频预算优化无法只看 token 总数，还要问任务依赖时间密度还是空间细节。

### 12.4 长视频需要分层浏览

一套常见流程先用低分辨率、低帧率扫过全片，得到镜头、字幕或事件候选。随后对候选时间段提高 fps，对含屏幕文字的帧提高分辨率。主模型回答时只接收相关片段与必要上下文。若答案置信度低，再回到时间索引获取邻近片段。

这种系统已经超出单次模型调用。它包含解码器、选择器、索引和多轮检索。报告结果时应计算所有视觉调用的 token 和延迟，并说明选择器是否使用问题文本。若选择器看到了问题，它也是推理系统的一部分。

视频字幕需要单独标记来源。原视频内嵌字幕属于画面证据，外部字幕文件属于额外文本通道，自动语音识别又会引入转写误差。VideoMME 等结果常分别报告有字幕和无字幕设置，部署评测也应保留这一差别。

### 12.5 一次点击操作怎样完成坐标闭环

假设屏幕分辨率为 2560 乘 1600，浏览器内容区截图为 2200 乘 1300。处理器为了预算把截图缩成 1100 乘 650，再在边缘补到网格整除尺寸。模型输出归一化坐标时，执行器需要先恢复处理器画布坐标，去掉 padding，再按缩放比例回到内容区，最后加上窗口偏移。

如果页面使用 150% 设备缩放，CSS 像素和物理像素还会不同。浏览器自动化通常以 CSS 像素操作，截图库可能返回设备像素。映射时必须知道每个接口采用哪一种坐标系。误差只要几十像素，就可能从确认按钮落到取消按钮。

动作后页面可能滚动、导航或弹出对话框。下一步不能继续使用旧截图上的框。执行器应等待页面稳定，重新截图，确认目标状态，再把新观察交给模型。高风险操作还要在执行前展示动作摘要和目标元素，等待用户确认。

| 坐标层 | 典型单位 | 必须保存的变换 |
| --- | --- | --- |
| 原始设备屏幕 | 物理像素 | 窗口位置与设备缩放 |
| 浏览器内容区 | CSS 像素 | 边框、工具栏和滚动偏移 |
| 截图图像 | 图像像素 | 裁剪区域与截图缩放 |
| 处理器画布 | patch 对齐像素 | resize、padding 和切片布局 |
| 模型输出 | 归一化坐标或 token | 归一化范围与输出格式 |

Qwen-VL 已经用 `[0, 1000)` 坐标支持 grounding。后续模型把相同思想延伸到 GUI 动作。坐标表示的一致性很方便，一次真实点击仍要经过上表全部映射。

### 12.6 多图输入的顺序也属于证据

多图比较常把图片顺序写进提示，例如第一张和第二张。处理器会把每张图片分别编码，再按消息中的顺序插入视觉段。若上游并发下载后按完成时间拼接，图片顺序可能悄悄改变。模型可能给出内容合理的回答，同时引用错误对象。

稳妥做法是为每张图分配稳定 ID，在提示中显式写出 ID 与用途，并在处理前后核对数组顺序。长对话里若重复引用旧图片，还要确认聊天模板是否重新插入视觉 token，或只保留文字指代。不同推理框架的缓存策略可能不同。

图片之间尺寸差异很大时，动态分辨率会让某一张占据大部分视觉预算。批量设置统一 `max_pixels` 只能限制单图，未必限制整条消息。应用层还需要总视觉 token 上限，并决定超限时缩小、裁剪或拒绝。

## 第十三章　从公开配置里还能读出什么

论文介绍设计动机，配置文件告诉推理代码实际构造哪些层。两者相互补充。配置只对应一个权重检查点，不能代替整代模型的论文。

### 13.1 四个代表性检查点

| 配置项 | Qwen-VL-Chat | Qwen2-VL-7B | Qwen2.5-VL-7B | Qwen3-VL-8B |
| --- | --- | --- | --- | --- |
| 视觉层数 | 48 | 32 | 32 | 27 |
| 视觉隐藏维度 | 1664 | 1280 | 1280 | 1152 |
| 注意力头 | 16 | 16 | 16 | 16 |
| 空间 patch | 14 | 14 | 14 | 16 |
| 时间 patch | 不适用 | 2 | 2 | 2 |
| 空间合并 | query 汇聚 | 2 | 2 | 2 |
| 语言隐藏维度 | 4096 输出接口 | 3584 | 3584 | 4096 |
| 特殊机制 | 256 learned queries | 动态分辨率与 M-RoPE | 窗口注意力与绝对时间 | DeepStack 与交错 M-RoPE |

表里 Qwen-VL 的 4096 指 adapter 交给语言模型的输出维度。它与后几代直接列语言隐藏维度的意义接近，结构来源却不同。把不同字段简单放在一列会掩盖架构变化，所以需要附上说明。

视觉层数减少也不能直接解读为视觉能力变弱。初始化模型、隐藏维度、训练数据、注意力形式和语言侧融合都发生了变化。参数数量只描述容量的一部分。

### 13.2 处理器配置是输入合同

Qwen2-VL 和 Qwen2.5-VL 的官方预处理器把最小像素写成 3136，把最大像素写成 12845056。两者恰好对应 4 到 16384 个 28 像素合并区域。这个范围说明处理器能接受的理论边界，模型服务仍可在调用时设更窄范围。

Qwen3-VL 的预处理器改用最短边总像素 65536 和最长边总像素 16777216。字段名与数值都改变了。直接把上一代的 `min_pixels`、`max_pixels` 参数复制到新处理器，可能无效或产生不同含义。迁移代码时应读取当前处理器文档和对象属性，不能只改模型 ID。

视频处理还要核对 `fps`、`num_frames` 与后端行为。有的接口按目标 fps 解码，有的接口先均匀选择固定帧数。若同时提供两个参数，优先级需要查当前版本。保存处理器最终返回的网格和时间元数据，比记录调用前参数更可靠。

### 13.3 位置配置为什么不能靠名字猜

Qwen3-VL-8B 配置启用交错 M-RoPE，分段为 24、20、20。Qwen3.5-27B 同样启用交错形式，分段改为 11、11、10。分段总和与对应模型的旋转位置维度有关，不应跨模型复制。

位置外推设置也与模型和运行时绑定。官方模型卡可能提供 YaRN 等扩展建议。扩展超过原生 262144 时，应分别测试长文本检索、长视频定位和短输入质量。某项任务在 500K 可用，不能推出所有任务在约 1M 都稳定。

位置编号的实现错误往往不会立刻报错。模型仍能生成流畅文字，只是在远距离引用、空间关系或时间定位上退化。最小测试集应包含短文本、长文本、多图、长宽图和不同 fps 视频，覆盖各坐标方向。

### 13.4 DeepStack 配置不能跨代默认继承

Qwen3-VL-8B 的 `deepstack_visual_indexes` 为 8、16、24。Qwen3.5-27B 的同名列表为空。两者视觉塔很多尺寸相同，却没有相同的注入设置。这是阅读配置比只看架构图更有价值的例子。

空列表说明这个 27B 检查点不会按该字段选择三个视觉中间层。它不能证明整个 Qwen3.5 家族所有规模都关闭 DeepStack，也不能证明训练期间从未使用类似机制。精确表述应限定到所检查的官方配置。

推理框架若硬编码假设存在三个索引，迁移到 Qwen3.5 时可能取空值或错误层。使用官方架构注册和处理器比手工套用旧版类更稳妥。第三方高性能后端也需要明确宣布支持相应模型类型，名字相近并不保证算子路径兼容。

### 13.5 Qwen3.5-27B 的混合层怎样排布

27B 配置列出 64 个语言层类型。三个 `linear_attention` 后接一个 `full_attention`，重复 16 次。若运行时只实现普通自注意力，模型无法按原结构加载。即使能够转换，速度和数值行为也可能偏离官方实现。

全注意力层采用分组 query attention，24 个 query 头共享 4 个 KV 头。这样能降低 KV cache。线性注意力层拥有独立的 key 头、value 头和状态维度，它的缓存形态与普通 KV 不同。服务框架需要同时管理两类层状态。

397B-A17B 采用相同三比一节奏，共 60 层。它还是 MoE，每层路由与注意力计算叠加。长上下文服务的瓶颈可能在权重通信、线性状态更新、全注意力层或视觉 prefill，需用真实请求剖析，不能只根据理论复杂度判断。

### 13.6 模型卡会更新，引用应带日期或 revision

官方模型卡可能补充推理建议、修正表格和更新框架版本。论文也可能从初版更新到后续版本。本文更新时间为 2026 年 8 月 19 日，文中配置以当日官方公开检查点为准。

严谨实验可以保存 Hugging Face commit revision 或仓库提交哈希。模型权重大文件无需重复下载才能记录 revision，API 与本地缓存都能显示提交。博客 URL 不能固定内容版本时，至少保存访问日期和关键表格截图或网页归档。

引用官方来源也要区分权重许可与网页内容许可。配置数字和事实可以引用，论文图表若要在博客展示，应检查许可和署名。本文的九张图全部用 HTML 重新绘制概念关系，没有复制论文原图。

## 第十四章　从五代变化提出四个研究问题

### 14.1 视觉压缩应该发生在哪里

Qwen-VL 在 adapter 处把视觉输出压成固定 256 枚 token。Qwen2 之后主要通过输入缩放和 2 乘 2 合并控制长度。Qwen3-VL 又让中间视觉特征绕过上下文长度，经 DeepStack 注入隐藏层。三种位置各有不同损失。

输入端压缩最省计算，却可能在识别前丢掉小字。视觉塔末端压缩已经支付视觉编码成本，但能用语义特征决定保留什么。隐藏层注入保留多尺度信息，不增加 token，却与语言架构耦合更深。未来设计需要根据任务选择压缩点，或让模型在低成本预览后请求局部高分辨率证据。

这个问题可以用受控实验研究。固定总 FLOPs，分别分给更高输入分辨率、更多视觉层、更多输出 token 或 DeepStack merger。任务应同时包含自然图像、OCR、计数和空间定位。只测一个平均分无法看见压缩位置偏向哪类证据。

### 14.2 视觉 token 是否应该拥有不同价格

当前上下文通常把每枚视觉 token 和文本 token 都当作序列位置。它们的生成职责不同。视觉 token 主要在 prefill 出现，不需要逐个生成。文字 token 既参与 prefill，也形成输出。视频中连续 token 还高度冗余。

混合注意力已经改变语言层处理长历史的成本。更进一步可以为视觉和文本设计不同缓存、稀疏访问或层级摘要。难点是语言推理随时可能回看某个小区域。压缩过早会让后续问题失去证据。

评估这类方法时，应报告完整端到端成本。把视觉 token 在某些层丢弃会降低语言计算，若前面额外运行昂贵选择器，总体未必更省。正确比较需要包含视觉塔、选择器、语言 prefill、解码和多轮回看。

### 14.3 时间应该写进位置、文本还是外部索引

Qwen2.5-VL 把绝对时间编码进 M-RoPE，Qwen3-VL 把时间戳写成文本。外部视频系统还会维护可检索时间索引。三种表示可以共存。

位置编码紧凑，适合让注意力感知间隔。文本时间戳便于生成和解释。外部索引可以覆盖远超上下文的视频，并支持回看。它们之间需要一致的时间基。若文本标签写 10 秒，位置编号按错误 fps 映射到 8 秒，模型会接收冲突信号。

研究时可构造变帧率、剪辑跳转和长静止段，分别测试事件顺序、绝对时间和持续时间。普通均匀短视频容易让多种时间表示得到相近分数，无法暴露差异。

### 14.4 统一模型怎样保持专业视觉能力

Qwen3.5 把多模态变成主模型默认能力。统一训练便于共享语言知识、工具接口和长上下文。训练数据中各模态比例若失衡，专业 OCR、细粒度定位或长视频能力仍可能被通用文本目标稀释。

公开材料没有完整数据采样权重，外部研究可以从行为侧测量。固定模型规模和输入预算，比较纯文本、图像、视频与工具任务之间的干扰。再观察小规模继续训练是否提高一个领域同时损害其他能力。

统一模型的价值最终要落在系统简化与能力迁移上。若一个权重能够在同一对话里读文档、看操作录像、调用计算器并回到页面执行，它减少了模型路由和上下文搬运。若专业任务仍需独立模型，统一主干也可以承担规划，专业模块负责高精度感知。两种形态都需要清楚记录证据怎样传递。

## 第十五章　从旧版迁移时逐项检查什么

### 15.1 先保存旧系统的可复现实例

迁移前选取一组真实输入，保存原始媒体、最终提示、处理器输出尺寸、生成结果、延迟和显存。样本要覆盖极宽图片、极长图片、小字文档、多图、短视频、长视频与坐标输出。平均 benchmark 无法替代这些边缘情况。

旧系统若依赖自定义聊天模板或图像占位符，也要把模板文本保存。换模型后先使用新模型官方模板，再逐项加入业务指令。直接套用旧模板可能丢失图片起止标记、时间戳或工具定义。

### 15.2 不要沿用旧 token 估算公式

Qwen-VL 的 256 是 adapter 输出常数。Qwen2 与 Qwen2.5 可按 28 像素合并网格估算。Qwen3 的代表配置使用 32 像素合并网格。视频还要考虑时间 patch、帧采样和处理器总预算。迁移脚本若继续假设每张图固定 256 token，限流与显存预估会严重偏低。

最可靠的做法是让当前处理器实际编码一批样本，读取视觉网格或输入序列长度，再建立经验模型。服务端应在请求进入 GPU 前估算成本，对超预算输入给出缩放、分段或拒绝策略。

### 15.3 重新校准坐标与结构化输出

不同代模型可能生成点、框或动作对象，坐标范围和推荐提示也可能变化。迁移时建立一组已知目标位置的截图，验证从模型输出到原屏幕的完整映射。测试应覆盖 padding、裁剪、高 DPI 和滚动页面。

JSON 输出要用正式解析器检查，不要靠正则从自然语言中截取。字段名称、动作枚举和数字范围应由 schema 限制。模型升级后若格式正确率下降，可以先调整官方推荐模板和约束解码，再判断是否需要微调。

### 15.4 分开测试质量回归与系统回归

质量回归关注答案、定位和动作是否正确。系统回归关注吞吐、首 token 延迟、峰值显存、批处理稳定性和长请求超时。新模型分数更高，可能因视觉 token 更多而让服务容量下降。只有两组测试同时通过，迁移才算完成。

视频还要测试解码失败、损坏时间戳、可变帧率和超长输入。图片要测试透明通道、旋转元数据、灰度图和超大像素。处理器对异常媒体的行为属于生产可靠性，不会出现在常规 benchmark 中。

### 15.5 保留回退和双跑窗口

新旧模型可以在一段时间内对同一请求双跑，只把旧系统结果返回用户，新结果用于离线比较。这样能发现业务分布上的退化，也能测量真实成本。涉及隐私数据时，双跑必须遵守原有数据范围和保留策略。

切换后仍保留按请求回退的能力。模型服务、处理器和执行器版本应绑定发布，避免只回退权重却继续使用新处理器。若 GUI 动作或高风险文档抽取出现异常，可以立即停止自动执行，回到只读建议模式。

### 15.6 用一张迁移表收尾

| 检查项 | 通过标准 |
| --- | --- |
| 模型与处理器版本 | revision 固定，官方模板已验证 |
| 图片预算 | 代表样本的缩放尺寸与视觉 token 可解释 |
| 视频预算 | fps、帧数、时间戳和总 token 有日志 |
| 输出协议 | JSON、框和坐标通过 schema 与映射测试 |
| 质量回归 | 核心任务和边缘样本达到约定阈值 |
| 系统回归 | 延迟、显存、吞吐和超时满足服务目标 |
| 安全措施 | 高风险动作确认、日志与回退均可用 |

迁移工作看起来比替换模型 ID 繁琐，却能把最常见的隐藏变化提前暴露。多模态系统的输入处理比纯文本系统更长，任一环节改变都可能影响结果。把这张表留在发布记录里，比只保存一份 benchmark 总分更有用。

## 结语

拿到一个新的多模态检查点，可以先用同一页文档和同一段视频跑一遍处理器。打印缩放后的宽高、视觉网格、实际帧数、时间戳和输入长度，再看模型答得怎样。这几项记录往往比宣传页上的总参数更早暴露成本和证据缺口。

接着打开配置，核对 patch、空间合并、视觉注入、注意力类型和原生上下文。论文解释设计缘由，配置限定当前权重实际采用的结构。两类材料放在一起，才能判断一个结果来自更好的模型、更多输入，或运行时换了默认设置。

最后把处理器 revision、输入预算、延迟和输出协议写进实验记录。下一次换模型时，这份记录能让同一批输入接受同条件比较，也能告诉部署者哪些参数需要重新校准。五代 Qwen 的变化很大，比较它们仍从一张图片实际变成多少 token 开始。
